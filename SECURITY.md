# Security Policy

This project is actively developed and maintained on a best-effort basis.
Only the latest code on the `main` branch is considered supported.

## Found a security issue?

If you think you’ve found a security problem, please **don’t open a public issue**.

Instead:

* Use GitHub Security Advisories, or
* Reach out to the maintainer directly on GitHub

A short explanation of what’s wrong and how you found it is more than enough.

## About fixes & contributions

I don’t always formally announce or document every security fix I make.

That said, **if you’re contributing a security-related fix**, please:

* Mention what you fixed
* Say (briefly) why it matters
* Avoid posting exploit details publicly

This helps keep things clear and avoids breaking stuff later.

## What this covers

* App logic and data handling
* UI behavior that could impact user trust or safety
* Build or config issues that introduce real risk

## What it doesn’t cover

* Cosmetic or non-exploitable issues
* Problems caused by modified setups or third-party dependencies

## Be cool about it

Please act responsibly and don’t abuse or publicly disclose issues before they’re fixed.
